DeerFlow 中文上手清单

        
      

      

        
适用范围：深度调研、任务编排、文件产出、线程记忆、工具调用、报告与网页生成。

        
能力总览：深度调研（网页检索/抓取/总结）、多步任务编排、生成 md/html/代码、线程内上下文记忆、调用搜索/抓取/文件读写/bash。

        
推荐操作路线：先定义目标与交付物 → 再给约束（时间、来源、格式）→ 上传材料 → 要求结构化输出 → 让它继续迭代补差。

        
文件上传后怎么分析：说明文件用途、要抽取的信息、输出格式；例如“读取上传的财报 PDF，抽取收入/毛利/费用/管理层指引，输出中文要点+风险表+3页汇报结构”。

        
如何让它生成网页/报告/代码：明确目标文件、目录、技术栈、验收标准；例如“生成单文件 HTML 仪表盘，包含图表占位、结论区、下载按钮，并输出到 runtime_data/artifacts/”。

        
可直接复制的提示词

        
1. 请对某行业做深度调研：检索近12个月一手资料，按市场规模、竞争格局、价格带、关键玩家、风险点输出中文报告，并附来源链接。

2. 基于上传的 Excel 和 PDF，先识别核心指标口径，再拆成数据清洗、异常检查、趋势分析、结论汇报四个子任务，逐步执行并输出结果文件。

3. 读取这份数据库 schema，生成可执行 SQL 分析方案：先列候选指标和维度，再给 SQL、结果解释、图表建议、PPT 页面结构。

4. 生成一个客户汇报网页：含封面、核心发现、图表区、建议动作、附录来源，输出 html/css/js 文件并说明如何本地预览。

5. 对这个代码仓做技术调研：说明模块职责、启动方式、关键依赖、风险点，并生成一份给新同学的中文上手文档。

        
高质量任务写法：目标 + 输入材料 + 分析维度 + 输出格式 + 约束条件 + 是否需要继续迭代。

      

    
    
      

        
角色 role 怎么用

        
      

      

        
role 决定这个字段在分析里扮演什么角色，不是备注，而是会影响后续查询计划。

        
metric 指标：拿来算数值。例：价格、销售额、销量。

        
dimension 维度：拿来分组。例：品牌、类目、颜色。

        
time 时间：拿来看趋势。例：上新时间、创建日期。

        
filter 过滤：拿来限制范围。例：性别、场景、是否新品。

        
最简单的记法：

        
按品牌看平均价格
品牌 -> dimension
价格 -> metric

看最近30天上新趋势
上新时间 -> time
价格/商品数 -> metric

只看女装里的品牌分布
性别 -> filter
品牌 -> dimension

      

    
    
      

        
配置中心流程用法

        
      

      

        
整体流程：创建场景 -> 写场景描述 -> 点 DB缓存读取数据库结构 -> 写本次推荐目标 -> 点推荐 -> 勾选字段/关系 -> 导入勾选 -> 去查询执行提问。

        
场景描述 是长期业务边界，创建场景时填写，决定这个场景大体围绕什么业务和数据范围。它不适合每次都改。

        
场景描述示例：
服装商品数据分析，围绕品牌、区域、类目、价格、上新、平台、库存等维度做分析。

品牌价格分析场景，重点关注品牌、平台、二级类目、价格带、折扣和时间窗口。

        
推荐目标 是当前这一次推荐的临时重点，基于当前场景和数据库结构返回不同候选字段/关系，供人工筛选。

        
推荐目标示例：
识别品牌中国和日本版本的区分字段，优先推荐品牌字典、区域字段和关联关系。

补充价格带分析需要的字段，优先推荐价格、吊牌价、折扣、时间和类目字段。

补充类目结构分析配置，优先推荐一级类目、二级类目、叶子类目和类目字典关系。

        
怎么判断结果：推荐结果只是候选，不会直接生效。字段和关系进入“已选列表”后，还要点击“导入勾选”，才会写入当前场景配置。

        
常见用法：同一个场景可以多次推荐。第一次补品牌/区域，第二次补价格，第三次补类目。每次只勾选这次确认需要的字段和关系。

        
配置迁移：点击“导出配置”会生成 JSON 文件，包含当前场景字段、ER 关系和底部语义字段。客户机器选择“导入为新场景”即可复用同一套配置；“合并到当前场景”和“覆盖当前场景”会先显示预检结果，确认后才写入。

        
推荐配置完成后，可以去“查询执行”测试：
优衣库中国和日本最近30天价格带分布
各品牌在不同二级类目的价格区间占比
最近30天各平台上新SKU数趋势

        
如果 LLM 推荐不全或不准：直接用底部“场景语义配置区”手工补字段和关系。这里补的是场景底座，不是上面的导入清单；它会成为这套场景的长期语义配置，后续推荐和查询会沿用，但不会自动替代上面的已选导入列表。

        
手工新增字段示例：
语义名：标准纤维名称
table_name：dict_fiber_info
field_name：Name
role：dimension
说明：用于显示标准纤维名称。

语义名：纤维编码
table_name：clothing_fiber_info
field_name：Code
role：dimension
说明：用于关联服装纤维明细和标准字典。

手工新增关系示例：
left_table：clothing_info
left_field：Id
right_table：clothing_fiber_info
right_field：ClothingId
join_type：LEFT
note：服装到纤维成分明细。

left_table：clothing_fiber_info
left_field：Code
right_table：dict_fiber_info
right_field：Code
join_type：LEFT
note：纤维编码映射到标准纤维字典。

        
如果你的库不是按 Name / Code 组织，把上面的表名和字段名换成你库里的真实字段就行；但像这种字典树，最好先用视图把子树收口，再让场景去连这个视图。
