## 0. 一句话交付结论

规划里 M1 只要求「对话 + 维度卡 + 图表卡」，实际本轮**一次做穿了 M1 与 M2 的主干**：
说一句「复盘 Zara」→ 出 4 张维度卡 → 点选维度 → 原地出图（area/column）→ 一句话生成 4 页大纲（已出图自动绑定）→ 生成 PPT → 右侧 16:9 预览 → 导出可编辑 `.pptx`。
全链路已在本机跑通并实测（含 PPTX 文件完整性校验）。

原有「场景配置中心 → SQL 展示」链路**完全保留**，新入口为独立页面，两者共用同一套领域服务。

## 3. 关键设计：画布产物协议（Artifact）

**画布上每个元素都是可寻址的 Artifact 卡片**，前端主循环只认 `kind` + 通用外壳，新增卡片类型不改主循环。

```json
{
  "artifact_id": "art_xxxx",
  "conversation_id": "conv_xxxx",
  "kind": "dimension_card | chart_card | outline_card | deck_card | note_card",
  "title": "...", "subtitle": "...",
  "status": "ready | failed | pending",
  "payload": { "由对应渲染器解释": "..." },
  "lineage": { "message_id": "...", "query_id": "...", "sql": "..." },
  "version": 2
}
```

- `kind` → 渲染器映射：`renderers[card.kind]`，未知 kind 走 `defaultCard` 兜底，不报错。
- **取数失败也留痕**：失败的维度会生成一张 `chart_card`（`status=failed`），payload 带 `error` 与真实 SQL，避免"点了没反应"。
- **可回退**：每次 revise 生成新 version，`rollback` 恢复上一版本。

## 6. 修复的真实 Bug：SQL 受控字段校验误判

**现象**：合法的品牌过滤 SQL `dbi.Name='ZARA（中国）'` 被 `find_controlled_sql_filter_issues()` 判为违规，直接拦掉所有纤维/面料相关查询。

**根因**：
1. `_sql_column_pattern()` 未防裸列名，`Name=` 被误当成 `dict_fiber_info.Name` 命中受控字段规则；
2. `_sql_table_aliases()` 无条件返回别名，导致表未被引用也算命中。

**修复**：`_sql_column_pattern()` 增加裸列名防护；`_sql_table_aliases()` 跟踪表是否被真正引用，仅在引用时返回别名。

**验证**：合规用例 → 0 issue（放行）；真违规用例 → 1 issue（仍拦截）。安全性未降低。

## 6.1 修复的真实 Bug：前端严格模式未声明赋值（用户实测发现）

**现象**：页面右侧画布**只剩一张维度卡**，对话区出现系统消息 `本次请求失败：node is not defined`。

**根因**：`agent.js` 的 `chart_card` 渲染器写成 `node = cardShell(...)`，**漏了 `var`**。
文件顶层有 `"use strict"`，严格模式下给未声明变量赋值直接抛 `ReferenceError`；
异常顺着 `renderCanvas` 的 `forEach` 冒出去，**导致其后的图表卡、大纲卡、PPT 卡全部静默不渲染**，
并被 `send()` 的 `.catch()` 捕获后显示为"本次请求失败"。

**为什么初版没抓到**：这是**运行时**错误而非语法错误——`node --check` 查不出来，
DOM id / API 路径 / 响应字段三项静态交叉校验也全部通过。**静态校验过 ≠ 页面能跑。**

**修复**：`agent.js:497` 补 `var`；对全文件做同类未声明赋值扫描 → 清零；
`agent.html` 缓存版本号 `m1 → m2`，避免浏览器沿用旧缓存。

**新增验证手段（本轮沉淀）**：在隔离 node 环境用 **jsdom** 做两套 harness——
`render_check.js`（真实渲染 + 断言卡片条数）与 `flow_check.js`（模拟完整点击路径）。
实测：五种卡片全部渲染、端到端交互流程（发消息→选维度→出图→要大纲→生成 PPT→切图型）零错误。
该方法已沉淀为可复用技能 `nobuild-frontend-backend-crosscheck`。

## 7. 如何运行

```bash

bash scripts/start_vibe_backend.sh          # 或见下
VIBE_PERSIST_STATE=1 <python> -m uvicorn apps.vibe_backend.app.main:app \
    --host 127.0.0.1 --port 18900

# 2) 前端（默认 18901）

# 3) 打开工作台
open http://127.0.0.1:18901/agent.html
```

- 页面右上角可切换**数据源 API 地址**（默认 `http://127.0.0.1:18900`），会记入 localStorage。
- 会话 ID 也会记入 localStorage，刷新后自动续写上一会话。
- 原「配置后台」入口保留在右上角「配置后台」链接（`index.html`）。

### 7.1 怎么进入新工作台（重要）

前端是 `python -m http.server` 托管 `static/`，**根路径 `/` 默认命中老工作台 `index.html`**，
新页面在 `agent.html`。三种进入方式：

| 方式 | 地址 / 操作 |
|---|---|
| 直接访问（推荐） | `http://127.0.0.1:18901/agent.html` |
| 从老页面进入 | 打开 `http://127.0.0.1:18901/`，点最顶部蓝色横幅「新版：对话式分析工作台 →」 |
| 桌面一键 | 双击 `~/Desktop/打开对话画布.command`（会自动拉起服务并打开浏览器） |

> 打开后**默认自动载入最新会话**，因此会立刻看到一份完整四阶段画布（维度卡 + 2 张图 + 4 页大纲 + 4 页 PPT 预览），

## 9. 已知限制（M1 有意识留的口子）

1. **意图路由是规则不是模型**：对极口语化/多意图混说的句子可能退化到 `explore`。降级是安全的（会追问），但不够聪明。
2. **无流式进度**：取数需等待（前端用固定文案"正在取数并出图（约 15 秒）…"占位），无 SSE 分阶段回传。
3. **PPT 预览是 HTML 近似版式**，非所见即所得的原生 pptx 编辑器；导出的 pptx 由 python-pptx 生成（图表以图片嵌入）。
4. **大纲页-图绑定为启发式**：按维度顺序挂载，未做语义级"这段话配那张图"。
5. **无鉴权/多租户**：与现状一致，M1 不做。
6. **会话持久化以 JSON 落盘**（`runtime_data/backend_state/state.json`），非 MySQL 表。
