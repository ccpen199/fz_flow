# 第五期工作总结：2026 年 9 月 · 对话式分析画布

记录范围：2026-09-01 至 2026-09-30，依据本仓库 9 月代码改动与配套文档整理。
上一期（第四期）记录范围为 2026-08-01 至 2026-08-31，落盘于 2026-09-04。

---

1、把表单式工作台升级为「对话流 + 动态画布」的会话式分析智能体。
左侧对话、右侧画布，按「意图启发 → 即时看数 → 脉络梳理 → 交付生产」四阶段组织。
新功能做成独立页面 `agent.html`，老工作台继续作为默认落户页、流程一行未改。

2、确立画布的核心数据模型：**每张产出都是可寻址的产物（Artifact），而不是聊天记录里的图片**。
维度卡 / 图表卡 / 消歧卡 / 澄清卡 / 大纲卡 / PPT 预览卡 共 6 类，按类型分派渲染，新增卡型不改主循环。
"PPT 的某一页 = 引用若干产物"——这样"改第 4 页""回退上一版"才有落点。

3、交付首版并跑通四阶段端到端验收。
真实会话实测：4 个分析切入点 → 2 张真实取数图 → 4 页大纲（其中 2 页自动绑定已出图）→ 4 页 PPT 预览 + 导出可编辑 `.pptx`（48973 字节 / 合法 OOXML / 4 页）。
服务重启后 5 个产物（含改过图型的版本号）完整恢复，验证了会话与画布的持久化续写。

4、补齐「字段消歧不能隐去」这一硬缺口 —— 这是"换个品牌就必然失败"的真因。
老页面的「字段消歧」本质是一个**人工确认动作**（把用户说法钉成标准值再进 SQL）；新链路一开始跳过了它，
于是下游的安全闸门永远关着：品牌一旦有多个候选（如 `THE NORTH FACE` 有 7 个变体）就直接拒执行。
新增三项能力：**消歧确认卡**（有候选就出卡让人选，有主导项才自动选）、**澄清卡**（口径不明/空结果时给选项）、
**参数抽屉**（价格带策略、桶数、时间窗），并把确认结果透传给两道 SQL 安全闸。
实测：THE NORTH FACE 从"4 个维度全挂"变为「消歧卡 → 点选 → 成功出图」；ZARA 无需确认直接出图。

5、多轮对话的意图判定从"关键词规则"升级为"LLM 判定"（接入 DeepFlow / deer-flow 的 LangGraph agent）。
规则路由退化为只负责抽槽位（品牌、时间窗、页数），意图由 LLM 判定并做严格 JSON 校验；
agent 不可用时如实回报"服务不可用"，**不退回关键词猜意图**。
同时确立一条设计原则：**给 agent 的是"事实"（画布上真实有什么），不是"结论"（有没有大纲）** ——
因此把 `has_charts` / `has_outline` 这类按产物类型的布尔开关，改造成通用的画布快照 + 上一轮上下文。

6、确立并固化「新功能零假数据」硬约束。
把三个容易混淆的概念分清：① 硬编码**规则/词表/阈值**（意图词表、消歧阈值、价格带桶数）= 允许，是逻辑参数；
② 伪造或改写**业务数值与记录** = 禁止；③ **展示截断** = 允许，但必须如实声明总行数。
交付双层守卫脚本：静态层扫描新链路源码禁止造数写法，运行时层把画布上每张图卡的 SQL 回 MySQL **逐值复算**，失败非零退出、可挂 CI。

7、修掉一批由用户实测发现的真实缺陷（均附实测证据与回归守卫）。
- **图表白屏**：后端默认图表类型是 `column`，而 ECharts 没有这个类型 → 整条 series 被**静默丢弃**、不报错；已归一化为 `bar`，并新增"图表类型映射"闸门防止复发。
- **画布底部卡片被压扁**：弹性子项默认可收缩 + `overflow:hidden` → 画布永不出现滚动条，底部卡片被裁掉、点不到；已修并保留滚动位置。
- **改完大纲回退不了**：版本号永远推不上去（改动落在已存档对象上、历史快照存的是引用）。
- **确认动作不幂等**：同一条回复重复出现 17 次（连点两下即触发），已加幂等闸门。
- **"问能力却出画布 / 说不要画布却出大纲"**：判定边界修正，并删掉一处违规兜底（无大纲时自己造一个）。
- **服务启停静默失败**：停服没等端口真正释放、启服只判"端口在监听" → 停止再启动之后服务反而是死的，退出码却是成功；已改为"等端口真空闲 + 健康检查判活"。
- **改了前端用户还看到旧页面**：静态服务器不返回缓存头导致 HTML 本身被缓存；已换成带缓存策略的前端服务。
- **第一轮好、第二轮起必然失败**：环境注入的代理变量把本机请求写成了绝对 URL；已在启动脚本里剥离代理变量。

8、完成 P0/P1/P2 批次的"让用户直接动手改产物"能力（只动新页面，老页面零改动）。
- 图表卡：底层 SQL 可编辑并重跑（只放行单条 SELECT/CTE）、图表↔数据表切换、形态下拉、自然语言改筛选与时间窗（真下推到 SQL）、上一轮写法保持粘性。
- 大纲卡：拖拽排序、新增/删除页、版式切换、单页重新取数、批量补齐待取数。
- PPT 预览：标题/洞察/结论所见即所得编辑，保存后自动重排预览；导出可编辑 `.pptx`。
- 工程侧：新增页面动作单测 15 条；新增一键自查脚本（后端单测 + 零假数据守卫 + 图表类型映射 + 前端语法）。

9、产出可交接的文档与手册（共 10 余篇）。
对话式画布改造评估与实施规划、首版实现说明、遗留方案备选清单、字段消歧与参数可控实现说明、
零假数据约束与校验、真实会话逐轮拆解、36 个功能点逐点详解、全链路流程图与功能点手册（HTML）、
四模块产品规格差距分析、P0–P2 落地说明。

10、与业务方对齐「智能体场景与使用对象」的四项待拍板事项，并给出一条可复现的技术根因。
场景的自动匹配仍是"关键词打分 + 全不命中落默认场景"，且打分平手时**先遍历到的胜出** ——
实测"价格带分布""价格带怎么分布""看价格带的走势"三类问法**都抢不到价格带场景**；
这与"意图已改为 LLM 判定且不允许兜底"形成两套标准。已把"请给一套规则"拆成三件可点选的事：
优先级判定、边界样例落点、兜底行为（追问还是落默认）。
