# 卡片侧按需配置 + 标准词典精确同名优先（2026-10-15）

> 报障来源：用户两张截图，会话 `conv_df1e16c2e4`（追问"为何回羊毛"）与
> `conv_5152ebdb28`（两张卡报"无法命中的标准值过滤" + 一张澄清卡）。
> 一句话需求：**"按需配置，场景也要接上卡片段……标准词典你处理好……指标兜底不允许。"**
>
> 结论：三条根因都在**新链路（`agent.html`）**，与"配置是否按需加载"这个需求本身无关 ——
> 判定侧一直是对的（逐轮 config_ids 实测每一轮都跟着那句话变），漏的是**下游的两处消费方**。

切入点卡的 payload 实测（`art_c1978913b3`）：


### 1.3 标准词典：用户说的**就是标准值本身**，却被判成不明确

```

```

## 2. 三条根因

| # | 根因 | 位置 | 后果 |
|---|---|---|---|
| 1 | **卡片侧没接上按需配置**：切入点卡的复用条件只看品牌，不看本轮配置 | `conversation_service._ensure_dimension_options` | 卡上的目标/指标/维度是上一套配置的，与本轮取数的字段对不上 → 废卡/澄清卡 |
| 2 | **指标兜底**：方向在本套配置里找不到自己的度量时，拿配置里第一个指标顶上 | `dimension_recommender.recommend` 的 `metrics[:1]` | 纤维配置里的"价格带与折扣节奏"被贴成 `各二级类目的纤维占比分布情况`、"品牌竞争格局"被贴成 `按品牌统计纤维占比` |
| 3 | **歧义判据把"名字里含它的下位值"也算进候选数** | `field_value_resolver_service._resolved_payload` | 精确同名命中被判 ambiguous → 取数闸门拦下 SQL（`find_unresolved_filter_conditions` → "无法命中的标准值过滤"） |

根因 2 是根因 1 的放大器：即使卡片跟着配置走，只要兜底还在，纤维配置内的"价格方向"依旧
会被贴上一个假指标；反过来，只要卡片错位，即使没有兜底，目标也会指向本轮没有的字段。
两条必须一起修。

## 3. 修复

### 3.1 卡片侧接上按需配置（根因 1）

* 新增 `_dimension_config_identity(conversation)`：返回 **`(本轮 config_ids 排序, "turn"|"session")`**，
  与既有的 `scene_for()` **同一口径**（跑过轮次 → 本轮 config_ids；一轮都没跑过 → 会话级并标
  `session`）。为什么要分 `turn`/`session`：配置是**轮次资源**，"本轮加载了 scene_X" 与
  "还没判定过、用建会话时那份 scene_X" 是两回事。
* 新增 `_dimension_card_matches_config(card, ids, source)`：卡上没记配置身份（本次改造之前建的卡）
  一律视为不匹配 → 原地重建一次。
* `_ensure_dimension_options`：**品牌 + 配置身份**都一致才复用；两个写卡入口
  （`_ensure_dimension_options` / `rotate_dimension_options`）都把 `config_ids` / `config_source`
  写进 payload（并顺手写进 `lineage.config_ids`）。`rotate_dimension_options` 必须一起改，
  否则用户刚"换一批"出来的那批会被下一轮判成"身份对不上"而重建掉。
* `_handle_data_query`：本轮配置重建后的卡里**没有** picked_keys 时，如实说明
  「本轮配置（X）里没有「key」这个方向——它属于上一套配置，所以我没按它取数。本轮可以切入：…」，
  而不是拿别的方向的指标硬凑一个目标。部分方向被挡下时，取到的照常给、挡下的如实说明。
* `apply_artifact_action`（确认标准值/口径/参数后重跑）从**会话级场景**改为 `scene_for()`：
  会话级 `scene_id` 只在建会话时猜一次、之后永不更新，拿它校验字段与推方向会出现
  "按 A 套确认的口径、拿 B 套的字段重算"。
* 判定**之前**那一步（agent 得先看到可选方向才能选方向）仍只能用画布上那张卡 —— 这是循环依赖，
  代码里写明了它的边界：那里给出的只是**给 agent 看的语义标签**，真正的方向校验在判定之后。

### 3.2 去掉指标兜底（根因 2）

`dimension_recommender.recommend`：

* 删掉 `if not chosen_metrics and theme["key"] != "trend": chosen_metrics = metrics[:1]`；
* 删掉第二处 `_preferred(chosen_metrics or metrics[:1], …)`；
* 找不到度量就**如实降级为计数**：`metric_names = _names(ordered_metrics, 3) or [COUNT_METRIC]`，
  `COUNT_METRIC = "记录数"`。这不是"从别处借指标"，而是与 `build_goal` 的空度量缺省、
  `canvas_orchestrator.plan_data_query` 的 `["记录数"]` 缺省**同一个口径**：卡片上显示的、
  目标里写下的、下游取数时用的是同一个词，不会分叉。

实测（真实配置中心，`scene_0004` 只有 9 个字段、唯一指标「纤维占比」）：

```
修复前  price   价格带与折扣节奏  metrics=['纤维占比']  goal=各二级类目的纤维占比分布情况
        brand   品牌竞争格局      metrics=['纤维占比']  goal=按品牌统计纤维占比
修复后  price   价格带与折扣节奏  metrics=['记录数']    goal=各二级类目的记录数分布情况
        brand   品牌竞争格局      metrics=['记录数']    goal=按品牌统计记录数
        fiber   面料成分与纤维混纺 metrics=['纤维占比']  goal=各标准纤维名称的纤维占比构成与变化   ← 不受影响
```

### 3.3 标准词典精确同名优先（根因 3）

`_resolved_payload` 增加 `exact_count`，歧义判据改成：

```python
if strategy in {"normalized_exact", "normalized_exact_with_note"}:
    ambiguous = (exact_count if exact_count is not None else len(unique_candidates)) > 1
elif strategy == "contains_candidate":
    ambiguous = len(unique_candidates) > 1
else:
    ambiguous = False
```

精确命中分支把 `len(exact_value_matches)` 传下去 —— 只数**精确同名**的条数。相邻的下位值
仍然原样列进 `candidates`（卡片上看得见），只是不再阻塞取数。

真实词典/配置核对（`scripts/verify_card_config_alignment.py` 运行时层）：

| 字段 | 用户说的话 | 结果 | 取数闸门 |
|---|---|---|---|
| `dict_fiber_info.Name` 标准纤维名称 | 羊毛 | resolved, **不歧义**, canonical=`羊毛` | 0 issue ✅ |
| `clothing_info.SubCategory` 二级类目 | T恤 | resolved, **不歧义**, canonical=`T恤` | 0 issue ✅ |
| `dict_brand_info.Name` 品牌 | 优衣库 | resolved, **仍歧义**（4 条精确同名） | 1 issue（仍然要问）✅ |

顺带修掉：报错文案的双句号（每条 note 自带句号，外层又拼了一个）——用户截图里那句
`请先在字段筛选中确认。。请确认字段值写法…` 就是它。

## 5. 影响面与剩余风险

* **老页面/老链路一行未改**：`index.html` 与 `/api/v1/analysis/sessions|sql-result-agent|scenes/*`
  走的是老命名空间；本次改动只在新画布的服务路径上生效。
* `field_value_resolver_service` 是**共用**的，判据放宽后老链路同样受益（更少误拦）；
  老链路里依赖"非品牌字段多候选即追问"的两条断言已按新语义更新。
* **仍待观察**：`fiber` 主题的 `prefer_metrics` 里带着 `价格`，所以在"有价格、没有纤维度量"
  的配置（`scene_prd_trend` / `scene_prd_structure`）里仍会推出 `各织造方式的价格构成与变化`。
  这一次它不再是"兜底"（价格确实在这套配置里），但主题名（面料成分与纤维混纺）与实际口径
  （织造方式 × 价格）仍不够贴。属于**主题词表策展**问题，未在本次改动范围内，已记入遗留清单。
* 卡片是"给 agent 看的方向标签"这一循环依赖没有被消除，只是把边界写清了：判定前的方向来自
  上一轮的卡，判定后会按本轮配置重建并复核。

## 6. 追加（同日）：验收过程中额外发现并修掉的两条

上面第 2 节的**三条**是用户报障的根因。写回归测试时又撞出两条同族的 incoherence ——
都不在原报障里，但都会让用户"被问一个自己没提过的东西"，因此一并修掉。

### 6.1 方向名被读成品牌（`intent_router._extract_brand`）

写"卡外方向仍可取数"这条守卫时，测试文案用了方向名本身（`看看 structure`），结果取数一步都没走：

```
看看structure  →  brand='UR'  →  「UR」在标准品牌字典里命中了 20 个候选，请选一个
```

根因很直白：`ur` 是种子品牌表里的真实品牌，而 **`ur` 恰好是 `structure` 的子串**，
`_extract_brand` 用的是 `if brand in lowered` —— 纯子串匹配。同类还有 `cos` ∈ `cost`、
`only`（本身就是英文常用词）。用户照着页面念方向名，却被弹一张从没提过的品牌消歧卡。

修复（只动新链路：`intent_router` 只有 `conversation_service` 一个消费方）：

* 英文别名编译成**整词**正则 `(?<![A-Za-z0-9])<alias>(?![A-Za-z0-9])`（`KNOWN_BRAND_PROBES`）。
  中文别名不受影响 —— 中文没有词边界，仍按子串匹配，识别面不缩小。
* 兜底抽取（识别种子表外的英文品牌）要排除**平台自己的方向词**：维度 key / 标题 / 别名
  （`structure`/`trend`/`color`/`price`/`fiber`/`brand`）是这一页的切入点名，不是品牌
  （`_brand_vocabulary(cards)`，词表取自真实配置中心，不现编）。
* 认不出就留空，不猜 —— 与"不确定就问"同一口径。

实测：

```
看看structure → ''        看看 UR 的价格带 → 'UR'     看看ur的价格带 → 'UR'
看看 trend    → ''        优衣库的纤维占比   → '优衣库'   看看 ZARA 价格带 → 'ZARA'
看看 color    → ''        生成 PPT 大纲      → ''
```

守卫：`tests/test_intent_router_brand.py`（4 条，词表取自真实配置中心；MySQL 不可达整体 skip）。

### 6.2 卡外方向被误拒（`_turn_dimension_options`）

页面上那张切入点卡只放 4 个入口（**版面取舍**），但"这一轮能不能按某个方向取数"必须按
**这套配置能服务的全部方向**判定。实测 `scene_0004` 能服务 5 个方向
（`brand/fiber/price/structure/trend`），卡里只有 4 个 —— `structure` 排在第五位。
按卡片那 4 个做判定，就会把用户/agent 点得到的方向判成"本轮配置里没有"。

修复：新增 `_turn_dimension_options(conversation_id, scene)`，返回全部方向
（`limit=MAX_DIMENSION_CANDIDATES`，不按卡片上限截断）；`_handle_data_query` 同时持有
**两份**清单 —— `card_options`（卡内 top-4，用于话术"本轮可以切入：…"）与 `options`
（全部方向，用于判定与取数）。判定**之前**给 agent 的那份合并视图同样不能截断（同一个理由）。

守卫：`test_turn_config.py::test_direction_outside_the_card_entry_points_is_still_executable`
（fail-closed：把 `limit` 改回卡片上限即变红）。
