# 受控字段消歧义操作说明

## 这项功能解决什么问题

用户输入的问题通常不是数据库里的标准写法，例如：

```text
uniqlo日本的所有T恤品类的棉纤维含量分布情况
```

系统会在生成 SQL 前，把可用于业务筛选的标准值字段统一解析：

| 用户说法 | 标准字段 | 处理结果 |
| --- | --- | --- |
| `uniqlo日本` | `dict_brand_info.Name` | `优衣库（日本）` |
| `T恤` | 场景配置的品类字段 | 例如 `clothing_info.SubCategory = 'T恤'` |
| `棉` | `dict_fiber_info.Name` | `棉` |

如果一个词命中多个字段或多个标准值，系统不会猜测，而是在页面显示候选项，等待确认。

## 客户按页面操作（不需要理解技术概念）

1. 打开系统，进入“场景配置/配置中心”。
2. 选择要分析的场景；没有合适场景时点击“创建场景”。
3. 在“字段”列表中确认要筛选的字段已启用，角色选择“维度”或“筛选”。例如：品牌、一级类目、二级类目、纤维、颜色、材质、功能。
4. 点击保存（或“推荐字段/关系”后勾选需要的字段），回到查询页面。
5. 在“问题/查询意图”直接输入问题，例如：`查询 T恤 的棉纤维`。
6. 等待“标准字段识别 / 歧义消歧义”面板出现，页面会把每个词和数据库候选一起列出来：
   - 自动识别且唯一的值会直接显示；
   - 多个候选时，在下拉菜单中选择正确字段和值。候选详情会显示命中条数及“共 N 个候选”；
   - 不希望作为过滤条件的词选择“不作为过滤条件”。
7. 点击“确认并生成SQL”。系统会自动把确认的标准值带入 SQL，不需要手工改 SQL。
8. 在“MySQL SQL & Run”区域查看 SQL、风险提示和执行结果；如果有问题，回到上一步重新选择候选即可。

### 本地库核对示例

当前测试库中，`T恤` 并不是只有一个值：

- `clothing_info.SubCategory = T恤`：4,353 条商品；
- `clothing_info.SubCategory = T恤/Polo衫/背心`：10,814 条商品；
- `clothing_info.Category` 中有 `T恤/Polo衫/背心`：10,814 条商品。

`dict_fiber_info.Name` 中包含“棉”的标准值共有 9 个：`棉、BCI棉、再生棉、彩棉、有机棉、木棉纤维、皮马棉、超仿棉、长绒棉`。因此输入“棉”时页面会显示多个候选，而不是只显示一个“棉”。

## 支持的字段类型

并不是数据库每一列都进行同一种消歧义：

- `controlled`：品牌、品类、纤维、颜色、材质、功能等标准值字段，使用候选值精确匹配；
- `numeric`：价格、占比等字段，解析数值、区间和比较符；
- `time`：抓取日期、上架时间等字段，解析最近 N 天、月份等时间范围；
- `free_text`：商品名称、描述等字段，只有用户明确要求关键词搜索时才使用文本匹配。

因此，新增一个未来的筛选字段时，优先把它配置为场景中的 `dimension` 或 `filter` 字段，并确保它能查询出标准值；通用解析器会自动参与识别，不需要再为每个字段写一套品牌式特例。

## 场景配置要求

要让字段出现在候选列表中，场景应满足：

1. 字段已启用，角色为 `dimension` 或 `filter`。
2. `table_name` 和 `field_name` 与数据库真实结构一致。
3. 品类、纤维等跨表分析已配置正确关系，例如：

```text
clothing_info.Id = clothing_fiber_info.ClothingId
clothing_fiber_info.Code = dict_fiber_info.Code
clothing_info.BrandCode = dict_brand_info.Code
```

4. 标准值字段能返回非空的低基数候选值。系统会将这些值放入 `value_resolution_context`，供页面确认和 SQL Agent 使用。

## 接口说明

页面调用：

```text
POST /api/v1/sql-result-agent/scenes/{scene_id}/analyze-intent-stream
```

接口以 SSE 流返回识别进度，最终事件包含：

```json
{
  "type": "complete",
  "analysis": {
    "terms": [
      {
        "text": "棉",
        "status": "resolved",
        "matches": [
          {
            "semantic_name": "标准纤维名称",
            "table_name": "dict_fiber_info",
            "field_name": "Name",
            "canonical_value": "棉"
          }
        ]
      }
    ]
  }
}
```

确认后，页面把 `confirmed_resolutions` 放入 SQL 生成请求。后端仍会再次校验受控字段；候选缺失、候选有歧义或 SQL 使用了模糊匹配时，会阻止执行并在页面显示原因。

## 排查方法

- 面板完全没有候选：先检查场景字段是否启用、字段角色是否正确、数据库是否能查询该列。
- 只有品牌有候选：检查品类/纤维字段是否被配置为 `dimension`/`filter`，以及数据库连接是否指向客户实际库。
- 候选过多：在页面选择正确值；不要直接把原始口语写入 SQL。
- 生成 SQL 被拦截：查看 SQL 区域的风险说明，通常是标准值未确认或使用了 `LIKE`。
