# 受控字段消歧义操作说明

## 这项功能解决什么问题

用户输入的问题通常不是数据库里的标准写法，例如：

```text
uniqlo日本的所有T恤品类的棉纤维含量分布情况
```

系统会在生成 SQL 前，把可用于业务筛选的标准值字段统一解析：

| 用户说法 | 标准字段 | 处理结果 |
| --- | --- | --- |
| `uniqlo日本` | `dict_brand_info.Name` | `优衣库（日本）` |
| `T恤` | 场景配置的品类字段 | 例如 `clothing_info.SubCategory = 'T恤'` |
| `棉` | `dict_fiber_info.Name` | `棉` |

如果一个词命中多个字段或多个标准值，系统不会猜测，而是在页面显示候选项，等待确认。

## 客户按页面操作（不需要理解技术概念）

### 已经配置好的字段：直接输入即可

1. 打开分析页面，选择已有场景。
2. 在“问题/查询意图”输入自然语言，例如：`查询 T恤 的棉纤维`。
3. 页面自动打开“标准字段识别 / 歧义消歧义”面板，并列出识别到的字段和值。
4. 如果出现多个候选，选择正确的一项；没有需要筛选的词可选“不作为过滤条件”。
5. 点击“确认并生成SQL”，随后在 SQL 区域查看执行结果。

### 需要新增或修改字段时：才去配置中心

1. 进入“配置中心 → 当前场景 → 字段”。
2. 新增或编辑字段，填写数据库表名、列名和中文名称。
3. 要参与自动识别，字段角色选择“维度”或“筛选”，并保持“启用”。
4. 保存后返回分析页面；之后用户只需输入问题，系统会自动识别这个字段。

页面候选的规则：

   - 自动识别且唯一的值会直接显示；
   - 多个候选时，在下拉菜单中选择正确字段和值。候选详情会显示命中条数及“共 N 个候选”；
   - 不希望作为过滤条件的词选择“不作为过滤条件”。

## 截图中为什么同一个词出现在多个字段

页面展示的是“这个词在当前场景已配置字段中的所有命中”，不是只查一个字段。比如一个场景同时启用了一级类目、二级类目、叶子类目，那么 `T恤` 可能同时命中这三列；这是场景配置和数据库列值的结果，不是系统把一个值复制了三遍。若业务只需要二级类目，在配置中心关闭其他类目字段即可。

每个候选后的“条数”是该表该列中这个标准值的记录数。同一个值在多个列都存在时，条数可能相同（例如三列都来自同一批商品），这不代表 SQL 会重复计算；最终是否去重由场景关系和查询指标决定。

当前页面会完整展开命中的候选（例如“棉”的 9 个标准纤维值都会显示），候选很多时仍会显示“共 N 个候选”作为总数提示。

### 本地库核对示例

当前测试库中，`T恤` 并不是只有一个值：

- `clothing_info.SubCategory = T恤`：4,353 条商品；
- `clothing_info.SubCategory = T恤/Polo衫/背心`：10,814 条商品；
- `clothing_info.Category` 中有 `T恤/Polo衫/背心`：10,814 条商品。

`dict_fiber_info.Name` 中包含“棉”的标准值共有 9 个：`棉、BCI棉、再生棉、彩棉、有机棉、木棉纤维、皮马棉、超仿棉、长绒棉`。因此输入“棉”时页面会显示多个候选，而不是只显示一个“棉”。

## 这次功能改动

- 不再只识别品牌；品类、纤维、颜色、材质、功能等已配置的筛选字段也会自动识别。
- 同一个词在当前页面启用的多个字段中都找到时，会全部列出，让客户选择。
- 候选会显示数据库条数和候选总数；确认后才会生成 SQL。
- SQL 使用数据库标准值，不直接使用客户输入的口语写法。

## 客户只需要记住两句话

1. 已经配置好的字段：直接在分析页面输入问题即可。
2. 要增加或更换可识别字段：才进入“配置中心 → 当前场景 → 字段”，启用该字段并保存；以后仍然只需输入问题。
