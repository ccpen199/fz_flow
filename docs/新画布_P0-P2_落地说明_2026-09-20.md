## 1. P0 — 用户说的话要真的落到图上

### P0-1 自然语言值筛选（「只看 400 元以上的价格带」）

**用户动作**：在对话里说一句带数值条件的话。
**链路**：agent 输出 `filters=[{field:价格, operator:>=, value:400}]` → 后端 `canvas_action_service.normalize_filters` 逐个校验（字段必须命中场景里**真实可查的语义字段**）→ 两路并行下推（intent 文本里写明「必须体现在 WHERE」+ `context.explicit_filters` 并入查询计划）→ 真取数。

**实测证据**（会话 `conv_b490e4f4a5`，真实 MySQL）：

```
卡片 SQL 片段：
  FROM clothing_info ci LEFT JOIN dict_brand_info db ON db.Code = ci.BrandCode
  WHERE db.Name = 'ZARA（中国）'
    AND ci.Price >= 400          ← 用户说的条件真的进了 WHERE
    AND ci.Price IS NOT NULL
卡片 payload.applied_filters = [{field:价格, operator:>=, value:400, display:"价格 >=400"}]
```

**本轮新增的可视化**：图表卡上出现「本次取数条件：`价格 >=400`」chips。
这一行不是复述用户的话，而是**校验通过、真正下推**的那几条（后端在写卡片时从已校验槽位落进 `payload.applied_filters`）。

**没落进 SQL 时会明说**：`filters_missing_from_sql` 只判断「字面量完全不在 SQL 里」这一种可证伪的缺失，命中就在回复里写「本轮有筛选条件没能落到 SQL 里」。找不到就报，找到不表态（可能只是巧合）。

### P0-2 自然语言换图表形态（「换成折线图」）

**用户动作**：说一句换形态。
**关键判断**：换形态是**纯展示**改动，不该重跑 SQL——同一 SQL 重跑一遍可能把用户刚看到的数字换成另一批。所以只有确实带了筛选条件才重跑，否则只改画法（`_handle_chart_tweak`）。

**实测证据**：

```
[canvas_revision] 把价格带那张图换成折线图
  → 已把《价格带与折扣节奏》换成折线图。数据口径没变，只是换了画法；不满意可以点「回退」。
  → spec[line x=品牌 y=价格带SKU数 series=二级类目 rows=60/164]   ← 行数完全没变，确实没重跑
```

**顺带修掉的一个真 bug（§3.2）**：卡片上的形态下拉框原来只写 `payload.chart_type`，而渲染读的是 `spec.chart_type` —— 选了折线，图还是柱子。

## 2. P1 — 用户要能直接动手改

### P1-1 图表卡的 SQL 可编辑 + 可重跑

**用户动作**：展开卡片底部的「底层 SQL（可改可重跑）」→ 改 → 「保存 SQL 修改」→「确认执行」。

**刻意分成两步**（与配置后台的 HITL 一致）：改完先落盘看一眼，确认无误再跑。保存**不执行、不推版本**（结果没变，版本号该由「结果真的变了」来推）。

**实测证据**：

| 操作 | 结果 |
| --- | --- |
| 保存原样 SQL | `200`，`version` 仍为 1，`history` 为空（保存 ≠ 改动） |
| 执行 | `200`，`rows_count=13`（与卡片原本的 13 行一致，说明是同一口径重跑） |
| 存 `DELETE FROM brand_dim` 再执行 | `409 仅允许 SELECT/CTE 查询。` |
| 存 `SELECT FROM WHERE` 再执行 | `409 MySQL 执行失败: (1064, "You have an error in your SQL syntax; … near 'FROM WHERE' at line 1")` |
| 上面两次失败之后 | 卡片仍 `status=ready`，`total_rows=13` —— **原图没被覆盖** |

失败时后端保留原图并给出真实原因，前端把它写进对话流（「SQL 执行未完成（图表保持原样）：…」）。把失败结果盖到图上，等于把用户已经看到的真实数据换成一片空白。

前端另有一处细节：输入框里还有**没保存**的改动时点「确认执行」，会先自动保存再执行——避免「跑的还是上一版」。

### P1-2 大纲页的要点/结论直改

**用户动作**：点某页的「编辑内容」→ 改「本页要点」（每行一条）与「业务解读 / 结论」。

**语义**：页面自己的内容一旦由用户给出，就成为该页的**权威内容**，编译幻灯片时优先于绑定图表卡自动生成的洞察。否则用户在预览区改的字会被「自动洞察」顶掉——改了跟没改一样。

**实测证据**（编译后的幻灯片，真实内容）：

```
slide rpage_3d37558400  findings=['用户写的第一条要点','用户写的第二条要点']
                        narrative='用户写的结论'      layout=chart_left
其余页（没有用户内容）   findings 来自图表卡片，narrative 来自图表卡片
```

### P1-3 大纲拖拽排序 + 新增空白页

**用户动作**：拖左侧序号换页序；点「新增一页」加一页空白页。

**实测证据**：

```
[200] add page rpage_3d37558400 → order 5 / title 「新增页 5」/ findings [] / narrative ''
[200] move to 1, changed=True   → 1 新增页 5 / 2 ZARA 竞品… / 3 上新节奏… / 4 价格带… / 5 品类结构分布
```

「新增一页」**不替用户编内容**：要点与结论留空，标题只给「新增页 N」这种位置性占位。

## 3. 这一轮修掉的三个真问题

### 3.1 拖拽排序是**静默失效**的（后端，已修）

`report_composer.move_page` 原来是：

```python
ordered.remove(moving); ordered.insert(target_index, moving)
self._reorder(ordered)     # ← 按每页当时记着的 order 字段排序
```

刚插进新位置的那一页还带着**旧序号**，`_reorder` 按旧序号一排序，立刻把它送回原位。接口回 `200`、`changed=False`、页序不变——拖了等于没拖，而且**没有任何报错**。

上一轮我曾把「`move_page` 返回 `False`」判定为「正确行为（无变化就不该推版本）」，**这个判断是错的**。本轮写单测时才发现：用一个真会改变顺序的场景（第 3 页挪到第 1 位）去断言 `changed is True`，直接失败。

修法：插完之后**按列表位置**重编号，不走 `_reorder`。

```python
for index, page in enumerate(ordered, start=1):
    page["order"] = index
```

### 3.2 「换图表形态」只写了一半（后端，已修）

`revise_artifact(chart_type=…)` 原来只写 `payload.chart_type`，而渲染读的是 `spec.chart_type` —— 从卡片下拉框选了折线，图还是柱子（一次静默的空操作）。现在同时落到 `spec`，并跟着改 `stack`（否则会出现「折线图却堆叠成一条」）。认不出的形态直接拒绝，不再接受一个改不动任何东西的值。

### 3.3 加一个条件，把刚选的画法重置回默认（后端，已修）

用户先「换成折线图」，再说「只看 300 元以上」——重跑取数重建 spec，形态被重置回默认柱状。**用户刚做的选择被悄悄抹掉。**

修法：`_execute_goals` 在写卡片前先看这张图上一次的形态，本次没点名形态就沿用（选择是粘性的）。

**实测证据**：

```
换成折线图              → spec[line ... rows=60/164]
再说「只看 300 元以上」  → spec[line ... rows=20/20]  filters=[价格 >=300]   ← 形态保持 line
```

## 4. P2 — 把「能聊到的粒度」补齐

### P2-1 换一批分析切入点

**用户动作**：维度卡右上角「换一批」。

候选来自场景自身字段语义推导出的**全部**主题，而不是重新编几个说法——「换一批」的意思就是「把还没看过的那几个给你」。看完一轮会如实说「已经都给你看过了」。

**实测证据**：

```
before: ['fiber', 'price', 'brand', 'color']
after : ['structure', 'trend', 'fiber', 'price']     新上来的: structure, trend
subtitle: 基于 竞品与价格 分析 的字段资产推荐 · 第 2 组
```

前端在换批后会把「已被换下去、但仍挂着勾选」的维度从选中集里摘掉——否则选中项会指向卡片上已不存在的选项。

### P2-2 指令式压缩（按主题合并）

后端 `compress_by_theme` 上一轮已完成：首页与末页**钉住**（各自是独立主题），中间分析页保留前 N 页，**被合并的页不是丢掉**，而是把标题/目标折进保留页的结论里（`（本页已合并：…）`）。前端无需额外控件——对话里说「大纲压到 3 页」即可。

### P2-3 单页重新取数 + 预览区直改 + 换版式

- **单页重跑**：`POST /outline/pages/{id}/regenerate`，其他页原样不动。
- **预览区直改**：幻灯片上的标题、数据洞察、业务解读都是 `contenteditable`，在预览里点开就能改。
- **换版式**：`chart_right / chart_left / chart_only / text_only` 四种，大纲页和预览区改的是同一个字段，pptx 导出用同一份。

**预览区直改的两个实现要点**（都是踩过才知道的）：

1. **焦点离开整块才提交**。三个可编辑区之间来回点不该触发保存——一次保存会引发整块重绘，把正在点的那个框换掉。
2. **保存后自动重新装配预览**。预览是投影，大纲改了不会自己变；不重排的话用户会以为「我改的字没生效」。
3. 判不出这一页对应哪个维度时**不猜**，如实说「第 2 页没有对应到具体分析维度」。

**实测证据**：

```
预览区把标题改成「预览区直改标题」→ 总线提示「正在保存这一页并重新装配预览…」
后端核对：outline page rpage_3d37558400 已改名；对应 slide.title 同步为「预览区直改标题」
单页重跑 → 409 第 2 页没有对应到具体分析维度，无法直接取数。（不猜，如实说）
```

### P2-4 批量补数调度

**用户动作**：大纲卡「补齐待取数（N）」。

逐页独立处理：某一页取不到数据**不打断**其余页，最后如实汇总哪些成了、哪些没成——批量操作最忌讳「跑了一半就停，用户还不知道停在哪」。

**实测证据**：

```
[200] fill-pending filled=1 failed=[]  → 已补齐：第 5 页
（该页随后出现在编译结果里：findings「布艺制品 的价格跨度最高，为 19,964。」等 3 条真实结论）
```

## 5. 一致性：大纲改了，已经存在的 PPT 预览要跟着重排

大纲是「源」，PPT 预览是它的**投影**。排序/增删/直改/补数之后，只要画布上**已经有**预览，就自动重新装配一次；没有预览就什么都不做（用户没要 PPT，不能凭空给他造一份）。

**实测证据**（拖最后一页到最前）：

```
outline 顺序：1 品类结构分布 / 2 预览区直改标题 / 3 ZARA 竞品… / 4 上新节奏… / 5 价格带…
deck 预览   ：P1价格带与折扣节奏 | P2品类结构分布 | …（同步重排）
```

## 6. 守卫脚本：不再允许「悄悄跳过」

`scripts/verify_chart_type_mapping.py` 原来在定位不到下拉框定义时**打印「跳过」并返回 0**。本轮改造后前端把形态清单改成了 `CHART_TYPES`，守卫立刻定位失败——于是它「通过」了，**什么也没挡**。

一个悄悄跳过的闸门等于没有闸门，而它挡的正是「图静默变白」这种最难发现的故障。改为：

1. 定位不到清单 / 定位不到类型映射 → **判定失败**（并提示「改过结构就同步本脚本的解析规则」）。
2. 前端清单必须与后端 `ALLOWED_CHART_TYPES` **逐个相等**（改了一边忘了另一边 = 说的和画的不一致）。
3. 历史取值（`column` / `vertical`）不得出现在画布下拉框里。

现状输出：

```
前端画布形态：['bar', 'line', 'area', 'pie', 'ring']
后端词表    ：['bar', 'line', 'area', 'pie', 'ring']
历史取值归一化：['column', 'vertical']
结论：✅ 画布形态前后端一致，且都能被 ECharts 正确渲染
```

顺带把 `canvas_action_service.py`、`report_composer.py` 补进零假数据守卫的链路文件清单（新链路服务文件必须同步登记）。
