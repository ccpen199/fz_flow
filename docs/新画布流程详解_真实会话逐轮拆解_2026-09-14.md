## 0. 一句话差别

**老页面**：你说一句话 → 生成一条 SQL → 返回一张表/图。一次问答结束。
**新页面**：你说一句话 → 先判"你想干什么" → 需要的话**反问你** → 结果沉淀成画布上**可寻址、可回退**的卡。所以"多轮"不是包装，是因为中间插了**必须由人拍板的关卡**。

## 2. 三道"人工关卡"的**精确**触发条件

这三道关卡是"多轮"的全部来源。每一道都能用公式判定，不靠感觉。

### 关卡① 字段消歧 —— 在**取数之前**拦下

**什么时候会问**：

```
候选 = resolve_field_value(品牌字段).candidates     # 按记录数排序
dominant = (候选数 ≤ 1)
        或 (top_count ≥ second_count × 3)          # 记录数碾压
        或 (top_count > 0 且 second_count == 0)
        或 (top_score ≥ second_score × 1.35)        # 没有记录数时退化为分数比

needs_confirmation = (候选数 > 1) 且 不是 dominant
```

**真实数字对照**（都取自 `clothing_info` 的实际记录数）：

| 你输入的品牌 | 候选（记录数） | 判定 | 结果 |
|---|---|---|---|
| `THE NORTH FACE` | 325 / **185** / 86 / 62 / 29 / 5 / 0 | 325 < 185×3=555 → **不是 dominant** | ❗**落消歧卡，一条 SQL 都不发** |
| `ZARA` | 3772 / 4 | 3772 ≥ 4×3=12 → dominant | ✅ 自动选定，直接出图 |

> 判定用的是**记录数**，不是"候选个数"。字典里 `THE NORTH FACE` / `THE NORTH FACE（日本）` / `北面（淘宝）` 这类变体本来就会归一化成同一个键，**"候选多"本身不构成疑问；"两个都像人话、量级还接近"才构成疑问。**

**你点选之后发生什么**（这是之前挂掉的地方）：
1. 写进 `working_memory.confirmed_field_values`（按 `term + 表 + 字段` 去重，同一会话**绝不问第二遍**）；
2. 这个值作为 `confirmed_values` **穿透下游两道 SQL 安全闸门**
   （`find_unresolved_filter_conditions` 管 filters；`find_controlled_sql_filter_issues` 管已生成 SQL 里的 `col = '字面量'`）；
3. 重新执行取数。

两个闸门的 `confirmed_values` 参数是**可选**的——老调用方不传 → 行为一字不变。

### 关卡② 口径澄清 —— 引擎**拒答**时

**两个触发条件（满足其一即可）**：

1. **空结果**：SQL 执行**成功**但 `rows` 为空。
   代码判定：`empty = (status == "succeeded" and not rows)`
2. **引擎要求补口径**：报错/备注文本命中这 6 个标记之一：

   ```
   未返回可执行 SQL ／ 缺少 ／ 需要确认 ／ 无法在不确认 ／ 需要明确 ／ 请先确认
   ```

**卡上给你的选项从哪来**：从引擎那句问话里正则反挖 —— `按[^、，。；;)）(（\s]{1,24}`，再按 `/` 拆开。
空结果这一支则固定给一个「**不限时间（看全部可用数据）**」，因为它要放开的是时间窗，不只是复述口径。

**自由输入框永远在**，因为这是启发式提取，会有挖不全的时候。

真实案例（`conv_7a4cccfb49`）：TNF 数据的最大抓取日期是 2025 年，而"最近30天"以**当天**为锚 → 0 行
→ 落澄清卡 → 点「不限时间」→ 重新取数拿到 **38 行**。在此之前这是一次**硬失败**。

### 关卡③ 参数抽屉 —— 取数**之后**调整

**哪里出现**：每张图表卡右上角「高级参数」。
**真正生效的范围**：价格维度（`isPrice`）才展开价格带控件；其他维度只给时间窗。

**白名单（只认这几个键，畸形 payload 改不动别的）**：

```
strategy ／ bucket_count ／ boundary ／ fixed_template ／ mode
```

改完点「重新取数」→ **复用同一个 goal 重跑** → `_upsert_artifact` 按 `dedupe_key` **覆盖同一张卡**（不是新增），并 `push_version` 记一版。
这就是第 6 轮那张卡能升到 v=3 的机制。

## 3. 画布上的"卡"是有身份的，不是一段 HTML

每张卡的字段：

| 字段 | 作用 | 真实例子 |
|---|---|---|
| `kind` | 决定前端用哪个 renderer | `chart_card` |
| `payload` | 这张卡的内容 | `spec.rows`（数据）、`sql`、`query_id`、`goal`、`findings` |
| `lineage` | **溯源凭据** | `{scene_id, scene_version, query_id, sql}` |
| `version` / `history` | 回退的基础 | 价格带卡 `version=3`、`history=[v1,v2]` |
| `dedupe_key` | 覆盖同一张卡而非无限追加 | `price` |

当前 6 种卡：`dimension_card` / `chart_card` / `outline_card` / `deck_card`，加上新增的 `resolution_card`（消歧）/ `clarification_card`（澄清）。
**新增卡型只需加一个 `kind` + 一个前端 renderer，不动对话主循环。**

## 4. 意图识别怎么判（规则，无 LLM）

5 类 + `unknown` 兜底，**关键词命中数加权打分 + 硬优先级**：

| 意图 | 权重 | 命中示例 |
|---|---|---|
| `rollback` | ×3 | 回退、撤销、上一步、恢复 |
| `report_build` | ×3 | ppt、汇报、大纲、串个、几页、片子 |
| `canvas_revision` | ×2 | 改成、换成、删掉、不要了、第4页 |
| `data_query` | ×1 | 出图、分布、占比、趋势、价格带、明细 |
| `explore` | ×1 | 有什么、哪些、建议、切入点、复盘 |

两条修正规则：
- 在维度卡上点选、或命中维度标题 → `data_query` **+4**（第 2 轮「纤维混纺」「价格带」就吃到了这条）；
- 全句零命中 → 画布空则 `explore`，已有图则 `data_query`（第 5 轮「好的，就这样」走的就是这条）。

**优先级比分数更决定结果**：`rollback > report_build > canvas_revision > data_query > explore`。
代码里专门写了注释解释原因——*"色彩不要了，直接生成 PPT"* 同时命中 revision 和 report_build，必须让 build 赢。

顺带抽三个槽位：品牌（`KNOWN_BRANDS` 28 个 + ASCII 品牌名正则）、页数（`(\d+)页`，钳制到 2–12）、时间窗。

## 5. 本次在真实数据里发现的**两个缺陷**（不是假数据问题，是新页面的健壮性问题）

### 缺陷 A：确认动作不幂等 → 同一句话被追加 17 次

在 `conv_7a4cccfb49` 里，同一条"已确认品牌「THE NORTH FACE」→ THE NORTH FACE（日本）"的助手回复**重复出现了 17 次**（28 条消息里只有 7 条是不同内容），澄清卡的 `version` 涨到 **18**。

**根因**：`_apply_resolution` / `_apply_clarification` **没有幂等保护** —— 每次调用都会
① 重新执行 `_execute_goals`，② 调一次 `_append_message` 追加回复。重复提交（双击 / 重试 / 测试重复点击）就线性放大。
前端也没有强制置忙。

**建议修法**：后端对已 `status=resolved` 的卡拒绝重复提交（或按 `(artifact_id, chosen)` 去重）；前端点击后立即置忙并禁用选项。

> 诚实说明：这 17 次大概率是我早前做交互测试时重复点击造成的，**但暴露的是后端确实缺少幂等保护**——真实用户双击同样会复现。

### 缺陷 B：跨轮上下文与当轮槽位拼接重复 → 图卡直接失败

同一会话里有一张失败卡的 `goal` 是：

```
THE NORTH FACE ZARA 各二级类目的价格分布情况（近30天）
```

**两个品牌被焊在一起**——`ZARA` 是前几轮的上下文，`THE NORTH FACE` 是当轮槽位，拼接时没有去重覆盖。
下游拿到这种输入直接拒绝执行，卡片标 `failed`，而报错还指向一个完全无关的原因。

**建议修法**：拼接上下文时，当轮槽位要**覆盖**而非追加同名槽位（品牌、时间窗都受影响）。

## 7. 边界（说清楚"什么不算假数据"）

- **展示截断**：图表卡最多画 60 行，但 `spec.total_rows` 必须等于真实行数（如实声明）。这是允许的。
- **LLM 生成的 SQL 写错** ≠ 假数据：查询失败 → 卡片 `failed` → **不展示任何数据**，与"编造数据"是两回事。
- **硬编码的规则/词表/阈值**（意图词表、消歧阈值 ×3、澄清标记词、页数钳制 2–12）是**逻辑参数**，允许且必要；它们决定"怎么算"，不决定"数是多少"。
