# 画布零假数据 · 约束与校验

> 约束来源：用户明确要求 —— **「老功能没有任何问题，但新功能（对话式画布）不允许用假数据。」**
> 建立日期：2026-09-14 ｜ 守护脚本：`scripts/verify_canvas_no_fake_data.py`

---

## 一、先把三件事分开，否则会误判

"假数据"这三个字很容易把三种完全不同的东西混在一起。本约束只禁止第 ② 种：

| # | 类别 | 是否允许 | 说明 |
|---|---|---|---|
| ① | **硬编码的规则 / 词表 / 阈值** | ✅ 允许（且刻意为之） | 意图关键词表、消歧阈值 ×3、价格带分桶数……这些是**逻辑参数**，不是数据 |
| ② | **假数据（伪造业务记录/数值）** | ❌ **禁止** | 凭空造出的品牌、销量、占比、趋势，或把真实值改写后展示 |
| ③ | **展示截断** | ✅ 允许，但**必须如实声明总数** | 图表卡最多展示 60 行，超出部分不画，但 `total_rows` 必须等于真实行数 |

①和②的区别是：① 决定"怎么算"，② 决定"算出来的数是不是真的"。

## 二、数据来源拓扑（证据）

新功能（对话式画布）与老 demo 是**两套完全独立的数据源**：

```
对话式画布（新）
  apps/vibe_backend (FastAPI)
        │  pymysql
        ▼
  MySQL 8.0.30  dataservice_test_local      ← 真实业务库，64 张表
    clothing_info / clothing_sale_info / clothing_fiber_info
    dict_brand / dict_brand_info / dict_clothing_pricerange
    vibe_scene / vibe_scene_field / vibe_input_correction_lexicon ...

老 demo（旧，与新链路无引用关系）
  demo/app/mock_data.py  ──►  SQLite  data/demo.db  (6.0 MB, 2026-03-20 后未变更)
                              品牌写死 Zara/Uniqlo/H&M/Only/Peacebird/Mo&Co
```

隔离证明：
- 全库搜 `sqlite3|demo.db` 在 `apps/vibe_backend` 与 `packages` 下 **零命中** —— 后端只会连 MySQL。
- 新链路（后端 + 前端）**没有任何一处 import / 引用 `demo/`**；唯一命中是 `analysis_sessions.py` 里的一句注释。
- 因此老 demo 的假数据**不可能**出现在新画布上。

## 三、画布取数的唯一通路

```
用户提问
  → SQL Agent 生成 SQL
  → MySQL 实际执行
  → query_run.result_preview          ← 唯一的数据出口
  → conversation_service.py:592
        rows = list(getattr(query_run, "result_preview", None) or [])
  → chart_spec_service.build(...)     ← 只做「分桶/取前 N 行/算 finding」
  → 落 chart_card.payload.spec.rows
  → 前端 agent.js  mountChart(target, spec)  ← 只读 spec.rows
```

关键点：

- **`conversation_service.py:592`** 是唯一入口，拿不到查询结果就是 `[]`（空），**不会兜底造数**。
- `chart_spec_service` 只做**变换**（列识别、分桶、取前 60 行、算 finding），不产生新数据。
- 前端 `agent.js` 无任何写死的数值序列；`series` 数组由 `rows` 逐点 `.map()` 算出（`hit ? toNumber(hit[yf]) : null`），无命中即 `null`（空点），不用 0 或平均值填充。
- 每个卡片都带 **`lineage`**（`scene_id` / `query_id` / 完整 `sql`），这是可回溯的凭据。

## 四、校验脚本：`scripts/verify_canvas_no_fake_data.py`

两层检查，失败即**非零退出**（可直接挂 CI 或提交前钩子）。

### 第 1 层 · 静态扫描（9 个新链路文件 + 8 个测试/脚本文件）

禁止出现"造数写法"，命中即失败：

- `random.*` / `np.random` / `faker` —— 用随机数生成业务数值
- `mock_data|dummy_data|fake_data|sample_data|demo_data|seed_data`、中文「假数据/模拟数据」类标识
- 同一行内把**含数字的字面量**赋给 `rows|data|dataset|series|points`（预烘焙数据集）

> 说明：`uuid4()` **不在**禁止之列 —— 它给会话/消息/产物/查询**发号**，属于标识符而非业务数据。
> `placeholder`（SQL 参数占位符）、`_UNBOUND_PLACEHOLDER_RE`（未绑定参数校验）等良性命中已列入 `ALLOWLIST` 并注明原因。

#### 1.1 测试脚本层：「打桩依赖」允许，「伪造结果」禁止

用户约束是「**不允许用假数据进行测试**」。这句话必须再切一刀，否则会把正常的单元测试也判成违规：

| 写法 | 性质 | 判定 |
|---|---|---|
| `monkeypatch.setattr(..., "get_scene", lambda ...: scene)` | 替换**依赖**（DB / LLM / 缓存） | ✅ 允许 —— 单元测试的必要手段 |
| `MagicMock()` / `lambda **kwargs: {"ok": True}` | 替身对象 / 空桩 | ✅ 允许 |
| `payload={"scene_id": ..., "global_goal": ...}` | 构造**请求**参数 | ✅ 允许（这是输入，不是结果） |
| `chart_spec={"rows": [{"维度": "A", "指标": 1}]}` | 伪造**结果**数据 | ⚠️ 需核实：若该值**不被断言**，属"结构占位" → 提示项；若被当作真实结果断言 → 失败 |

已核实的一处**结构占位**（每次运行都会提示，不阻断）：

```
apps/vibe_backend/tests/test_presentation_workflow_service.py:15
  chart_spec={"chart_type": "line", "rows": [{"维度": "A", "指标": 1}]}
```

它测的是**幻灯片修订逻辑**（append_slide / rule_plan / apply_revision），断言对象是"换成柱状图"后
`chart_type` 由 `line` 变 `bar` 这类**结构变化**，`rows` 里的数值从不参与断言。
**建议**（未动，等用户决定）：改名为 `_fixture_chart_spec()` 并注明「结构占位，非业务数据」，
这样任何人扫到都不会误以为它在用假数据当真实结果。

### 第 2 层 · 运行时回溯（最强证据）

遍历所有会话的 `chart_card`，取出卡里的 **SQL 与 `spec.rows`**，用**同一段 SQL 直连 MySQL 复算**，逐值比对。判定：

| 情形 | 判定 |
|---|---|
| 行数相等 且 逐值一致 | ✅ 全量透传 |
| 画布行数 < 真实行数，且为真实结果的**逐值一致前缀**，同时 `spec.total_rows` == 真实行数 | ✅ 正常展示截断 |
| 数值被改写 | ❌ 失败 |
| 画布行数 **超过** 真实行数 | ❌ 失败（凭空多出记录） |
| 截断但 `total_rows` 不实 | ❌ 失败（隐瞒） |

用法：

```bash
# 完整校验（静态 + 运行时）
env -u http_proxy -u https_proxy NO_PROXY='*' \
  ./.venv/bin/python scripts/verify_canvas_no_fake_data.py --limit 50

# 只跑静态层（无需后端在线）
./.venv/bin/python scripts/verify_canvas_no_fake_data.py --no-runtime

# 指定后端
./.venv/bin/python scripts/verify_canvas_no_fake_data.py --backend http://127.0.0.1:18900
```

## 六、已知边界与后续

1. **截断上限 60 行**（`chart_spec_service.build(max_rows=60)`）—— 允许，但依赖 `total_rows` 如实声明；守卫已把"截断不声明"列为失败项。
2. **LLM 生成的 SQL 质量问题不等于假数据** —— 例如 `Unknown column 'bucketed.raw_width'` 这类报错，是 SQL 写错（查询失败、卡片标 `failed`、不展示任何数据），与伪造数据是两回事。守卫对 `status != ready` 的卡片跳过比对。
3. **老 demo 的 `demo/app/mock_data.py` + `data/demo.db` 仍在仓库里** —— 已确认与新链路零引用，但同名容易让人误以为画布在用假数据。**如需彻底消除歧义，可将其移入 `third_party/` 或改名为 `legacy_seed`**（待用户决定，本次未动）。
4. 只要新链路新增服务文件，请同步更新脚本里的 `CHAIN_FILES` 清单（脚本对缺失文件会报 `[缺失]` 提示）。

---

## 七、一句话总结

**新画布不产生数据，它只搬运数据。** 数字全部来自 `query_run.result_preview`，即 MySQL 实际执行的查询结果；卡片的 `lineage.sql` 可随时复算验证。仓库里唯一的假数据在老 demo 的 SQLite 里，与新链路物理隔离。
